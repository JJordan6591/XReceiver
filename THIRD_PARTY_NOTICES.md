## Microsoft C++/WinRT

The project restores `Microsoft.Windows.CppWinRT` 2.0.220531.1 from `XReceiver/packages.config`. That package is the Microsoft C++/WinRT projection. Its license is MIT:

https://github.com/microsoft/cppwinrt/blob/master/LICENSE

C++/WinRT writes `Generated Files/`, including `module.g.cpp`, during the build. Those files are generated output. Do not edit or commit them.

## Visual Studio UWP template

`App` and `MainPage` started from the Visual Studio C++/WinRT UWP blank-page template (application boilerplate, XAML page shell, and manifest skeleton). The receiver, RTP, H.264, audio, settings, and UI behavior were written in this repository.

## UxPlay

UxPlay is a separate program. XReceiver does not include UxPlay source. UxPlay is GPL-licensed by its authors:

https://github.com/FDH2/UxPlay

Interoperating with UxPlay over RTP does not incorporate that program into this repository.

## Standards

Packet formats follow published specifications, including RFC 3550 (RTP), RFC 3551 (L16), and RFC 6184 (H.264 RTP). Those descriptions are not copied implementations from another media project.

## H.264 test clip

A file named `Assets/poc_1080p60.h264` was tracked earlier and then removed. It was 34,285 bytes, which is not a 600-frame 1080p60 encode, so those historical bytes were not treated as a verified test pattern. It is not in the release tree. The normal build does not require it. A contributor can generate a synthetic GStreamer `videotestsrc` pattern with the command in `CONTRIBUTING.md` and keep that file local. Do not commit generated media.

## What is not included

No RPiPlay, GStreamer, or FFmpeg source is vendored. No Apple, Microsoft, Xbox, or UxPlay logos are included. The tile images under `XReceiver/Assets/` are an original geometric mark (an X over a screen rectangle) generated by `tools/generate-tiles.ps1` from `assets/xreceiver-mark.svg`. They replace the Visual Studio placeholder tiles.
